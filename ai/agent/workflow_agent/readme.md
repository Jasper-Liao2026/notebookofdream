## AI Workflow 工作流
coze 构建工作流
选择节点    ( 输入、逻辑判断、输出、llm、图片生成....  输出)
需要智能融入既定流程，需要稳定执行的流程中
FDE 工程 Workflow 适合为流程性工作提效、自动化

Workflow 本质上是一套预定义的流程，可以把它想象成一套生产的流水线，每一步都有明确的输入输出，每个界节点的逻辑是固定的，当条件满足就会进入下一阶段

在技术上，通常变成一个编排好的工作流引擎
一个由ai调用，条件判断，循环逻辑组成的图谱


LangChain 是用于快速搭建工作流的开发框架

## 思考
AI 工作流也能干活，他和Agent(ReAct) 有何区别?
很多人会混淆，反正都是ai在执行任务


## Agent 智能体
和 workflow 逻辑完全不一样 ，他不在一条预设的轨道上，而是站在一个开放的空间里。自己探索怎么做
从技术角度，一个agent往往具备三个大的核心能力

第一个能力：感知环境
通过输入文本、图像、数据来理解任务。有哪些工具可以调用，当前情况如何，如何分布，如何规划
第二个能力：规划路径
不是预先定义好，而是动态去生成任务链
第三个能力：执行行动
去调用工具，完成子任务，并不断的去调整

## 举例
你让Agent去规划旅行，他可能会去搜索一下机票和酒店的价格，再去查天气和签证需求，然后结合你的偏好和预算，动态去权衡方案。
整个过程，他可能走的路径和你预期的完全不同，这就是agent的关键区别，自主性和适应性，他不会被一个固定的流程限制，而是像一个思考中的个体。所以，本质的区别在于WorkFlow是确定性的执行，agent是一个不确定的探索，workflow 就好像一条高速公路，路线很清晰很固定，效率很高，但能到达既定的终点。
Agent 更像一个老司机，他知道要去哪，但可以随时去改道，尝试新的路径，甚至在目的地发生变化的时候，自行调整

所以 ，从产业角度，workflow 更适合流程化，重复性的任务
比如审批流程、数据清洗、客服ai
Agent更适合动态的一个角色场景。比如：复杂搜索、策略规划

从技术栈的领域，workflow 更依赖于规则，图形化编排(coze),流程引擎，Agent更依赖于大模型的推理能力和记忆能力，包括他的工具调用等

未来我们的AI工程中将会集合Agent和workflow 的双重能力
底层是workflow去提供稳定性和可控性，上层是agent提供灵活性和智能性

workflow 是骨架，Agent是workflow的大脑
workflow 没有创造力，agent有，但是不可控，不可预测，一起结合，既高效又有智慧
