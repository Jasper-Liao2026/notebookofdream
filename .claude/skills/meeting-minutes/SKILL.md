# 会议纪要生成

根据用户提供的会议文字稿，生成结构化的会议纪要。

## 工作流程

### 阶段一：通读与预处理

仔细阅读用户提供的全部文字稿，理解会议的整体脉络。然后清理内容：

- **移除停顿词**：去掉"嗯"、"啊"、"那个"、"就是说"、"然后呢"等口头禅和无意义填充词
- **合并碎片句**：将因口语导致的断句、重复语句合并为通顺的书面表达
- **保留原意**：清理时不得改变发言者的原意，不确定的内容宁可保留原文

预处理后应该得到一份干净、连贯的会议内容文本。将此文本作为后续提取的基础。

### 阶段二：提取与结构化

从预处理后的文本中提取信息，填入以下四个板块。**所有不确定的内容一律留空**，不可编造。

#### 一、会议基本信息

提取以下字段：

| 字段 | 说明 |
|------|------|
| 会议标题 | 根据内容归纳一个简洁的标题 |
| 时间 | 会议的具体日期和时间 |
| 地点 | 线上平台/线下会议室名称 |
| 主持人 | 主持或控场的人 |
| 参会人员 | 列出所有参会者姓名和角色（如能识别） |
| 记录人 | 做会议记录的人（如有提及） |

#### 二、会议目标

- **会议目的**：本次会议要解决什么问题、达成什么决议
- **预算/资源**：涉及的预算额度或资源分配（如有提及）
- **背景信息**：会议召开的背景、前置条件、关联项目或事件

#### 三、会议内容

按主题划分，每个主题形成一个独立小节。对于每个主题：

- **主题名称**：用一句简短的话概括
- **讨论要点**：列出该主题下讨论的具体问题
- **各方观点**：记录不同发言人的观点、建议、顾虑，尽量标注发言人
- **结论/决议**：该主题讨论后达成的共识或结论（如无则留空）

如果会议内容跨越多个不相关的主题，务必拆分为多个小节，而不是揉在一起。

#### 四、行动项

以表格形式列出所有待办事项：

| 负责人 | 任务内容 | 截止时间 |
|--------|----------|----------|
| 张三 | 完成需求文档初稿 | 2026-07-20 |

- 每个行动项必须明确**谁**在**何时**之前完成**什么**
- 如果缺失任何一个要素，能推断的推断（基于上下文），推断不出的留空
- 如果某个行动项的状态在会议中有更新（如已完成、进行中），也一并标注

### 阶段三：输出检查

输出前按以下清单自查：

1. □ 四个板块是否完整？
2. □ 不确定的信息是否已留空而非编造？
3. □ 口头禅和停顿词是否已清理干净？
4. □ 会议内容是否按主题合理拆分了？
5. □ 行动项是否包含负责人、任务、时间三要素？
6. □ 全文是否使用客观、中立的语气（不添加评价性语言）？

## 质量原则

- **忠实原文**：纪要中的每一条信息都应能从原文中找到依据。不添加文字稿中不存在的信息。
- **宁缺毋滥**：无法确定的信息宁可留空，不可猜测。大语言模型容易"脑补"——这一点对于会议纪要尤其危险，因为错误的信息可能导致错误的决策。
- **口语转书面**：将口语化的表达转为正式的书面语言，但保持原意不变。
- **去除冗余**：同一观点如果被重复表达多次，合并为一次陈述。
- **结构化优先**：按主题组织内容比按发言时间顺序更有价值。读者的核心诉求是快速了解"讨论了什么、结论是什么、我接下来要做什么"。
